# Revision Notes

## How to revise

- Review 15–20 minutes before practice
- Solve one problem without notes before checking the solution
- Explain the logic out loud
- Write down what you forgot
- Revisit weak concepts after 2–3 days

## Common mistakes to watch

- Off-by-one errors in loops
- Confusing `==` and `=`
- Using the wrong data structure
- Forgetting base case in recursion
- Not testing edge cases
- Overwriting variables without tracking their purpose

## Good interview habits

- Clarify the problem first
- Think about input and output
- Write pseudocode before code
- Mention time and space complexity
- Test simple examples manually

## Important reminders

- Simpler code is easier to explain
- Readability matters more than cleverness in early practice
- A correct approach with clear reasoning is better than a compact but confusing solution

## Weak topics to revisit

- list slicing and mutation
- dictionary frequency counting
- two-pointer movement logic
- recursion base cases
- stack balancing logic
- complexity trade-offs
